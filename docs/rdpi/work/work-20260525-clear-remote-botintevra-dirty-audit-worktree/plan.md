# Plan

## Verification gate

This plan is intentionally narrow and operator-safe: it gathers live evidence only after independent plan review passes, preserves `audit/` before any cleanup, and does not delete tracked or unrelated files.

## Steps

1. Confirm remote access and botIntevra repository identity.
2. Capture readonly evidence:
   - `pwd`;
   - `git rev-parse --show-toplevel`;
   - `git status --short`;
   - `find audit -maxdepth 3 -type f` if `audit/` exists.
3. If `audit/` exists and is untracked, create a timestamped backup archive outside `/home/www/botIntevra`.
4. Verify backup contents.
5. Remove only `/home/www/botIntevra/audit` after backup verification.
6. Verify `git status --short` is clean.
7. Verify remote AIF state through concrete API/status checks:
   - `GET http://192.168.88.67/api/health`;
   - `GET http://192.168.88.67/api/tasks/5fd1ace1-ba50-4bc0-b604-56e65c7ca59d`;
   - create or retry one narrow botIntevra canary task through `POST http://192.168.88.67/api/tasks` only if needed to prove branch isolation;
   - poll `GET /api/tasks/:id` until the new task either proceeds past branch isolation or reaches a different terminal blocker.
8. Record whether the task no longer reports `Branch isolation failure (dirty_worktree)`.
9. Update intake/RDPI result and status.
10. Run repository/source checks from the local source tree only:
    - `git diff --check`;
    - Prettier check for changed files;
    - `npm.cmd test` as source-level unit/integration tests, without starting local AIF service, browser, or e2e;
    - `npm.cmd run lint`;
    - `npm.cmd run build`;
11. Use only remote API/status checks for this operational task's live service verification.

## Stop conditions

- Stop before cleanup if `audit/` contains files that do not look generated by AIF/canary execution.
- Stop if backup creation or backup verification fails.
- Stop if remote path is not `/home/www/botIntevra` or not a git repository.
