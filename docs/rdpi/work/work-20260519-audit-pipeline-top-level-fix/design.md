# Design

## Goal

Make audit roadmap batches produce executable source-report cards that satisfy the same evidence shape expected by deterministic report generation and strict validation. Prevent doomed audit cards from falling through to model execution and timing out.

## Non-goals

- Do not weaken the strict audit validator.
- Do not hide `source_inconclusive` when a genuinely invalid or impossible audit card is imported.
- Do not change `auditCardDecision` semantics; accepted cards should keep exposing `closed_verified`.
- Do not change unrelated runtime profile, deployment, or UI behavior.

## Approach

### 1. Make deterministic audit fallback scopes evidence-safe

Change deterministic audit roadmap fallback scope selection in `packages/api/src/services/roadmapGeneration.ts` so source cards use concrete, tracked, readable files rather than broad directories, hidden generated paths, or untracked runtime directories.

Expected properties:

- Prefer `git ls-files` when available.
- Ignore generated/hidden runtime roots such as `.ai-factory`, `.codex`, `.agents`, `.claude`, `.git`, `node_modules`, `dist`, `build`, `coverage`, and binary/media artifacts.
- Expand candidate directories into representative tracked text files.
- Keep each source card small enough for deterministic repair, typically 3-6 concrete files.
- Keep synthesis unchanged except for using the source report artifacts generated by the safer cards.

### 2. Make fallback risk hypotheses scoped and searchable

Replace generic fallback risk wording with file/scope-specific terms derived from the scope path and audit area. This avoids generic "owner-area defects" evidence that cannot match scoped files and that later appears as low-quality evidence.

Expected properties:

- Risk ids remain `risk-*`.
- Every risk mentions the exact scope root.
- Risk text includes searchable path/area terms such as `config`, `service`, `timeout`, `test`, `runbook`, or the file stem, rather than generic filler.

### 3. Fail fast for non-repairable audit report cards

In `packages/agent/src/subagents/implementer.ts`, add a deterministic pre-runtime guard:

- If a task has a roadmap report artifact and is not locally repairable from declared scope roots, terminalize it as `source_inconclusive` with precise scope diagnostics.
- Do this before building a free-form runtime implementer prompt.
- Keep `manualReviewRequired=false`; this is a deterministic contract failure, not a manual-review request.

This keeps bad imported cards visible but prevents Qwen tool-turn exhaustion.

## Risks and mitigations

- Risk: scopes become too narrow and miss broad architectural context. Mitigation: fallback source cards still cover multiple owner areas and representative files; broad analysis can be produced only when the generator can attach concrete evidence.
- Risk: hidden generated files become unaudited. Mitigation: hidden/generated paths remain valid only when explicitly requested by a custom audit roadmap; deterministic fallback avoids them because they commonly produce validator noise.
- Risk: existing tests expect broad `Scope: src` style fallback. Mitigation: update tests to assert concrete tracked files instead of broad directories.
